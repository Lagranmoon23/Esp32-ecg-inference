# v1.0 不足与改进清单

生成日期：2026-10-31

本文档记录 v1.0（`esp32_ecg_inference_v1.0`）在代码审计中发现的已知不足，以及对应的技术改进建议。按「影响程度」与「改动成本」排序，用于指导 v1.1 的开发优先级。

## 阅读说明

- **严重度**：🔴 正确性 / 结构性硬伤，🔴🟡 边界，🟡 鲁棒性，🟢 工程可维护性。
- **成本**：改动量级（是否需要重训、是否需要新硬件、是否改动模型）。
- 每条都标注了涉及的文件与函数，方便定位。

---

## 一、正确性层面

### 🔴 1. 低置信度拒识「算好了却没接进实时链路」

- **位置**：`firmware/main/ecg_model.cpp` 的 `top_two_margin()` 与 `infer()`。
- **现象**：代码里已经实现了 `top_two_margin()`（前两名 logit 差），`run_golden_test()` 也打印了 margin，但**实时推理路径 `infer()` 只做 argmax，完全不消费 margin**。
- **影响**：边界样本被硬判，S 类 F1 只有 0.6296 很大程度上是边界样本被强行归类。
- **建议**：在实时链路当 `top_two_margin < 阈值` 时输出 `UNKNOWN`（或 `LOW_CONF`），而不是硬猜。这是**改几行就能落地**的高收益项，无需重训。

### 🔴 2. 推理队列丢拍导致「beat 时间轴错位」

- **位置**：`firmware/main/app_main.cpp` 的 `sample_task()`，`xQueueSend(g_beat_queue, &features, 0)`。
- **现象**：队列满时用超时 `0` 静默丢拍。但丢拍时该 R 峰**已经 append 进 `EcgPipeline::peaks_` 历史**，只是它的 beat 特征没进推理队列。后续 `build_inputs()` 的 `pre_rr` / `post_rr` 用的是「包含被丢 beat」的 peak 序列，而分类的是另一个 beat——**时间轴对不上**。
- **影响**：隐蔽的正确性 bug，会导致 RR 特征与分类目标错位。
- **建议**：推理 90 ms 远快于心搏间隔（约 600–1000 ms），队列几乎不会满。二选一：
  1. 改用 `xQueueSend(..., portMAX_DELAY)` 阻塞；
  2. 丢拍时把该 peak 从历史回滚，保持序列一致。
  推荐方案 1。

### 🔴 3. 采样抖动未量化，而 R 峰定位对抖动极敏感

- **位置**：`firmware/main/app_main.cpp` 的 `esp_timer` 周期回调 + `xTaskNotifyGive` 唤醒采样任务。
- **现象**：360 Hz 采样用的是定时器单次 ADC 读取（`adc_oneshot_read`），整条链路的**实际采样时刻抖动没有被测量**。
- **影响**：交接实验已证明切窗位置偏移会损失约 0.03 的 Macro-F1。抖动决定 R 峰定位精度上限，也决定 `RPeakDetector` 的 `kRefineBefore / kRefineAfter` 窗口是否够宽。
- **建议**：在 v1.1 动手前，先加采样时间戳统计（记录 `esp_timer_get_time()` 相邻差，算 p50 / p99 抖动），把「360 Hz 到底准不准」变成数字，再决定是否升级 ADC continuous/DMA。

### 🟡 4. `post_rr` 隐含「未来信息」，端到端延迟未显式建模

- **位置**：`firmware/main/ecg_pipeline.cpp` 的 `build_inputs()`。
- **现象**：`post_rr` 用的是 `peaks_[index+1] - peaks_[index]`（下一个 R 峰），因此分类一个心搏必须等**下一个 R 峰到来**。同时 `local_rr` / `global_rr` 的 `interval_median` 遍历到 `index-1` 为止，是纯历史，二者时序混用。
- **影响**：功能上能跑（README 已注明「约一个心搏的算法延迟」），但延迟是隐式的，不利于后续做时间平滑与时间轴对齐。
- **建议**：把「post-RR 依赖」显式建模成固定 N 拍延迟的流水线，并在文档写明「端到端延迟 = R 峰确认延迟 + 1 个 RR 间隔 + 推理 90 ms」。

## 二、鲁棒性层面

### 🟡 5. 滤波重连后的初始条件可能被运动尖峰污染

- **位置**：`firmware/main/ecg_dsp.cpp` 的 `SosFilter::push()`。
- **现象**：初始化用 `states_[i].z1 = kFilterZi[i][0] * sample`（用第一个样本填稳态初始条件）。若 `reset()` 后第一个样本是运动尖峰（毫伏级跳变），初始条件被污染，后续几百个样本的滤波都偏。
- **影响**：重连瞬间的伪差会拖垮一段时间的滤波输出。
- **建议**：`EcgPipeline` 重连后（`disconnected_` 恢复分支）丢弃前 N 个样本（如 360 个 = 1 秒）再进入统计与滤波稳态。README 里「约 10 秒建立统计」目前没有覆盖滤波器状态收敛。

### 🟡 6. `lead_is_off()` 只能判断完全脱落，不能判断接触不良

- **位置**：`firmware/main/app_main.cpp` 的 `lead_is_off()`。
- **现象**：直接读 GPIO 电平，AD8232 的 LO+/LO- 只能判断「电极完全脱落」，不能判断「接触不良导致的间歇性伪差」。
- **影响**：移动尖峰可能被误判为 R 峰。
- **建议**：这是 P0 SQI 的核心，且**基础数据现成**——`RollingNormalizer` 已有 MAD，`RPeakDetector` 已有 envelope。可加滑动窗口的幅度突变率 / 斜率超限计数（如 1 秒内 `|filtered|` 跳变超过 X 倍局部 MAD 即标记伪差），汇总成质量分数。

## 三、结构性层面

### 🟡 7. 单拍分类缺少跨拍时间上下文

- **位置**：模型输入为单拍 `[198]` + 6 个 RR 特征。
- **现象**：模型内部没有跨拍状态。心律失常（尤其是 S 类 vs 正常早搏的区分）本质是「节律模式」，单拍信息天然不足。
- **影响**：S 类 F1 上不去的结构性原因之一。
- **建议**：两条路，v1.1 评估后选：
  1. **轻量**：不动模型，输出端做 3–5 拍投票 / 指数平滑（下一版重点第 4 条已列）。
  2. **更彻底**：连续 3 拍 beat 拼接成 `[3,198]` 输入，或在 embedding 后加时间维度的轻量 attention/GRU。代价是重训 + 重新量化。

## 四、工程 / 可维护性层面

### 🟢 8. `ecg_generated_config.hpp`（302 KB）是生成物却被当作源码

- **位置**：`firmware/main/ecg_generated_config.hpp`。
- **现象**：302 KB，黄金向量、滤波系数、RR 统计全部内嵌，由 `export_firmware_assets.py` 生成。
- **建议**：
  1. 在 README 明确「生成物，改脚本后重新生成，勿手改」；
  2. 更彻底：把黄金向量拆成 `models/golden.bin` 走 `EMBED_FILES`（与 `ecg.espdl` 一致），config header 只留系数（几 KB），大幅提升可读性。

## 五、优先级建议（v1.1 路线）

按「收益 / 风险 / 成本」排序：

| 优先级 | 条目 | 是否需要重训 | 是否需要新硬件 |
|---|---|---|---|
| P0 | #1 低置信度拒识接实时链路 | 否 | 否 |
| P0 | #3 量化采样抖动 | 否 | 否 |
| P0 | #2 修推理队列丢拍时间轴错位 | 否 | 否 |
| P1 | #5 滤波重连后丢弃前 N 样本 | 否 | 否 |
| P1 | #6 SQI（基于现成 MAD/envelope） | 否 | 否 |
| P1 | #4 显式化 post-RR 延迟 | 否 | 否 |
| P2 | #7 时间平滑 / 跨拍上下文 | 视方案 | 否 |
| P2 | #8 拆分黄金向量为独立资产 | 否 | 否 |

前四条（P0 + #5）是**不需要重训、不动模型、风险低**的改动，改完即可让实时链路更稳、更可信。建议 v1.1 从这些入手，再推进 SQI 与运动传感器等结构性功能。
